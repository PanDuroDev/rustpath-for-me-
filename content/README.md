# دليل كتابة المحتوى

كل صفحة درس تُبنى من ملف Markdown واحد. أنت تكتب المحتوى والبيانات فقط، والموقع يرتب الصفحة والاختبارات تلقائيًا.

## أين أضع الملف؟

- المراحل: `content/stages/<رقم>.md`
- الدروس: `content/lessons/<رقم>-<slug>.md`

اسم ملف الدرس يبدأ برقم من خانتين، مثل `05-verify-rust-toolchain.md`. الرقم والـ`slug` يُستخدمان في رابط الصفحة.

## بيانات أعلى الملف

كل ملف درس يبدأ بكتلة بين `---` و`---`:

```yaml
---
id: 5
stage: 2
slug: verify-rust-toolchain
title: التحقق من Rust وفهم rustc
summary: تحقق من تثبيت Rust وافهم دور المترجم.
status: upcoming
kind: lesson
minutes: 25
objectives:
  - التحقق من إصدار Rust.
  - فهم دور rustc.
---
```

| الحقل | مطلوب | المعنى |
| --- | --- | --- |
| `id` | نعم | رقم الدرس، فريد في المنهج |
| `stage` | نعم | رقم المرحلة التي ينتمي إليها |
| `slug` | نعم | أحرف إنجليزية صغيرة وأرقام وشرطات فقط |
| `title` | نعم | عنوان الدرس |
| `summary` | نعم | جملة تظهر في البطاقات وصفحة الدرس |
| `status` | نعم | `done` أو `active` أو `upcoming` |
| `kind` | لا | `lesson` (افتراضي) أو `project` |
| `minutes` | لا | مدة تقديرية بالدقائق |
| `objectives` | لا | قائمة أهداف الدرس |
| `draft` | لا | `true` لإخفاء الدرس من «المتاح» وإظهار تنبيه الإعداد |
| `evidence` | لا | دليل مختصر يظهر في سجل التقدم |
| `remaining` | لا | ما تبقى في الدرس النشط |

### قواعد الحالة

- `done`: الدرس مكتمل.
- `active`: الدرس الحالي للمتعلم. لا تضع أكثر من درس نشط واحد.
- `upcoming`: درس قادم.
- الدرس النشط لا يكون `draft: true`.
- الدرس `done` لا يكون `draft: true`.
- عند إضافة محتوى درس جديد: أزل `draft: true`، ثم اضبط `status` حسب موقعه.
- إذا أردت ترك درس قادم بلا محتوى، اجعله `status: upcoming` و`draft: true`.

## بنية الدرس

البنية المقترحة:

1. شرح مختصر للمفهوم.
2. أمثلة وكود.
3. تدريب عملي باستخدام `:::checklist` و`:::notes`.
4. اختبار واحد أو اثنان باستخدام `:::quiz` مع أسئلة متنوعة.

لا حاجة إلى كتابة `## اختبر فهمك` قبل `:::quiz`، لأن كتلة الاختبار تنشئ رأسها بنفسها.

## Markdown المدعوم

- عناوين `##` و`###` و`####`، وتُبنى منها فهرسة تلقائية في أعلى الدرس عند وجود ثلاثة عناوين أو أكثر.
- فقرات وقوائم نقطية ومرقمة، مع قوائم متداخلة عبر الإزاحة بمسافتين.
- قوائم مهام ثابتة: `- [x]` و`- [ ]`.
- اقتباسات `>`.
- جداول أنبوبية، مع محاذاة الأعمدة عبر صف الفواصل: `:---` لليمين، `:---:` للوسط، `---:` لليسار.
- كتل كود بثلاث علامات خلفية مع اسم اللغة، ويمكن إضافة اسم ملف بين قوسين:
  ` ```rust [main.rs] `.
- كود سطري، عريض `**نص**`، مائل `*نص*`، شطب `~~نص~~`، وتظليل `==نص مهم==` بخلفية صفراء.
- كسر سطر داخل الفقرة: أضف مسافتين أو `\` في نهاية السطر.
- روابط وصور. الروابط الخطرة مثل `javascript:` تُحذف.

### الصور

ضع ملفات الصور في `content/images/` ثم أشر إليها بمسار نسبي:

```md
![وصف الصورة](images/example.png)
```

- تُنسخ الصور تلقائيًا إلى الموقع عند البناء.
- إذا أشرت إلى صورة غير موجودة، يفشل البناء ويذكر اسم الملف الناقص.
- إذا كانت الصورة وحدها في فقرة، تُعرض مع تعليق أسفلها مأخوذ من نص الوصف البديل.
- يمكن إضافة عنوان للصورة: `![وصف](images/example.png "العنوان")`.

### صناديق التنبيه

ثلاثة أنواع متاحة، وكلها تقبل Markdown عاديًا بداخلها:

```md
:::note
ملاحظة توضيحية.
:::

:::tip
فكرة تساعدك على الحل.
:::

:::warning
خطأ شائع يجب تجنبه.
:::
```

كل HTML الخام يُعرض كنص، لذلك لا تستخدم HTML داخل Markdown.

### أقسام قابلة للطي

استخدم `:::details` لإخفاء شرح طويل أو إجابة اختيارية خلف ضغطة. العنوان اختياري، والمحتوى يقبل Markdown كاملًا:

```md
:::details لماذا نحتاج ownership؟
شرح مفصّل يظهر فقط عند الضغط.
:::
```

بدون عنوان يظهر «تفاصيل» تلقائيًا. لا تضع `:::` داخل القسم نفسه.

## كتلة الاختبار

كل مجموعة أسئلة تبدأ بكتلة `:::quiz`:

```md
:::quiz
id: lesson-05-check
title: اختبر فهمك
description: ثلاثة أسئلة قصيرة.
pass: 70
:::
```

- `id` مطلوب وفريد داخل الدرس.
- `title` و`description` اختياريان.
- `pass` نسبة النجاح من 0 إلى 100، والافتراضي 70.
- يجب أن تظهر `:::quiz` **قبل** أسئلة المجموعة.
- كل سؤال في المجموعة يستخدم `group` مساويًا لـ`id` الخاص بالاختبار.
- كل معرف سؤال (`id`) فريد داخل الدرس.

## الأسئلة

### اختيار من متعدد — إجابة واحدة

```md
:::single
id: q1
group: lesson-05-check
prompt: ما وظيفة rustc؟
hint: فكر في المترجم.
explanation: rustc يترجم كود Rust إلى برنامج.
- [ ] إدارة الحزم.
- [x] ترجمة الكود.
- [ ] عرض الملفات.
:::
```

- علامة `[x]` على إجابة واحدة فقط.
- علامة `[ ]` على بقية الخيارات.
- خياران على الأقل.

### متعدد الإجابات

```md
:::multiple
id: q2
group: lesson-05-check
prompt: أي مما يلي من مزايا المترجم؟
- [x] يفحص الكود قبل التشغيل.
- [x] ينتج ملفًا تنفيذيًا.
- [ ] ينفذ كل سطر فورًا.
explanation: المترجم يفحص وينتج ملفًا، لكنه لا ينفذ سطرًا بسطر.
:::
```

- ضع `[x]` على كل إجابة صحيحة.
- إجابة صحيحة واحدة على الأقل.

### صحيح أو خطأ

```md
:::truefalse
id: q3
group: lesson-05-check
prompt: تحتفظ RAM بالبيانات بعد إيقاف الجهاز.
answer: false
explanation: RAM ذاكرة مؤقتة.
:::
```

### إجابة قصيرة

```md
:::short
id: q4
group: lesson-05-check
prompt: ما اسم مجموعة الخطوات المرتبة لحل مشكلة؟
answers: الخوارزمية | خوارزمية | algorithm
placeholder: اكتب كلمة واحدة...
case_sensitive: false
explanation: الخوارزمية هي سلسلة خطوات مرتبة.
:::
```

- افصل بين الإجابات المقبولة بـ`|`.
- تتم المقارنة بعد حذف المسافات الزائدة والتشكيل، ودون حساسية لحالة الأحرف افتراضيًا.
- استخدم `case_sensitive: true` إذا كانت الحالة مهمة.

### إجابة مكتوبة

```md
:::long
id: q5
group: lesson-05-check
prompt: اشرح الفرق بين المترجم والمفسّر.
model: |
  المترجم يترجم الكود كاملًا قبل التشغيل، بينما المفسّر ينفذ الكود خطوة بخطوة غالبًا.
- [ ] ذكرت أن المترجم ينتج برنامجًا.
- [ ] ذكرت أن المفسّر ينفذ خطوة بخطوة.
:::
```

- لا تُصحح تلقائيًا، ولا تدخل في نسبة النجاح.
- زر «اعرض الإجابة النموذجية» يكشف النموذج.
- عناصر `[ ]` بعد النموذج تظهر كقائمة مراجعة ذاتية.

## كتل مساعدة

### ملاحظات

```md
:::notes
id: my-notes
title: مساحة ملاحظاتك
prompt: دوّن ما فهمته.
placeholder: اكتب هنا...
rows: 6
:::
```

### قائمة مهام تفاعلية

```md
:::checklist
id: my-practice
title: تدريب عملي
prompt: نفّذ الخطوات ثم ضع علامة.
- [ ] الخطوة الأولى.
- [ ] الخطوة الثانية.
- [ ] الخطوة الثالثة.
:::
```

الملاحظات والاختيارات تُحفظ في متصفح المتعلم فقط. لا تكتبها في `_site` ولا ترسلها إلى أي خادم.

````md

status: upcoming

minutes: 25
objectives:
  - طباعة نص في الطرفية.
  - كتابة تعليق مفيد.
---

## الطباعة

استخدم `println!` لطباعة سطر:

```rust
fn main() {
    println!("مرحبًا!");
}
```

## تدريب

:::checklist
id: printing-practice
title: تدريب
- [ ] اطبع اسمك.
- [ ] اطبع رقمًا.
:::

:::quiz
id: lesson-10-check
title: اختبر فهمك

:::

:::single
id: q1
group: lesson-10-check
prompt: أي ماكرو يطبع سطرًا؟
- [x] println!
- [ ] print!
- [ ] format!
explanation: println! يطبع النص ثم يضيف سطرًا جديدًا.
:::
````

## أخطاء شائعة

- نسيان إغلاق الكتلة بـ`:::`.
- كتابة `group` لا يطابق `id` الخاص بـ`:::quiz`.
- وضع `:::quiz` بعد أول سؤال في المجموعة.
- وضع أكثر من `[x]` في سؤال `:::single`.
- تكرار `id` سؤال.
- نسيان `draft: true` لدرس قادم بلا محتوى.
- وضع أكثر من درس `active`.

عند وجود خطأ، سيفشل بناء GitHub Actions برسالة تحدد الملف والسطر. صحّح الخطأ ثم ارفع التغيير مرة أخرى.

## النشر

1. عدّل الملف من GitHub.
2. ارفع التغيير إلى `main`.
3. انتظر انتهاء `Build and deploy RustPath`.
4. افتح الموقع وتحقق من الصفحة.

لا تحتاج إلى تثبيت Node أو تشغيل أوامر على جهازك. كل الاختبارات والبناء والنشر تتم في GitHub Actions.
